# 저장 형식 호환성 계약 (Compatibility Contract)

- **작성일:** 2026-11-20 · 근거 커밋 `e6c32bf` (`build/sec-core.js` 등)
- **목적:** 현장 PC 브라우저에 이미 쌓인 암호화 자료를 **재구성 중에도 무손실로 읽어 들이기** 위해, 바꾸면 안 되는(또는 바꾸려면 마이그레이션이 필요한) 저장 형식을 고정한다.
- **규칙:** 이 문서에 적힌 키 이름·포맷은 **재구성 단계에서 임의로 바꾸지 않는다.** 바꿔야 하면 "기존→신규" 마이그레이션 코드와 테스트를 먼저 만든 뒤에만 바꾼다. 모든 단계의 통과 조건에 "이 계약 준수"를 포함한다.

---

## 1. 키 유도 / 암호화 파라미터
- KDF: **PBKDF2-SHA256**, 반복 `ITER = 310000`(기본), salt **16바이트** 무작위.
- 대칭키: **AES-256-GCM**, `extractable:false`, IV **12바이트** 무작위(암호화마다 새로).
- 비밀번호 최소 길이 `MIN_PW = 8`.
- 비밀번호 자체는 어디에도 저장하지 않는다.

## 2. localStorage
| 키 | 내용 | 포맷 |
|---|---|---|
| `fireplan_*` (접두어 `fireplan_`) | 각 서식의 작업 데이터 | 암호문 문자열 `"WSEC1:" + base64( IV(12) ‖ ciphertext )`. 평문 UTF-8 문자열을 암호화한 값. |
| `woomi_sec_meta_v1` | 암호 확인용 메타 | **평문 JSON**: `{ v, salt(b64), iter, check, created, changed?, site, manager }`. `check` = `encStr(key,"woomi-ok")` (암호 검증값). `site`·`manager` 는 **현재 평문**(향후 암호화 시 마이그레이션 필요). |
| `woomi_sec_idle_min` | 자동 잠금 분 | 평문 숫자 문자열 (5/10/30/60/120). |

- 앱 코드는 `localStorage.getItem/setItem` 을 그대로 쓰고, `Storage.prototype` 후킹이 `fireplan_*` 값을 투명하게 암·복호화한다.
- `WSEC1:` 접두어가 없는 `fireplan_*` 값은 **예전 평문 자료**로 간주해 읽고 다음 저장 때 암호화한다(레거시 마이그레이션 경로).

## 3. IndexedDB
- DB 이름(고정): `fireplan_b3a_db`(교육·훈련), `fireplan_hotwork_db`(화기작업), `fireplan_b56_db`(안전점검). 버전 `1`, object store `"kv"`.
- 값 포맷:
  - 암호문: `{ __wsec:1, iv:Uint8Array(12), ct:Uint8Array }` — `ct` = AES-256-GCM(`JSON.stringify(value)`).
  - `__wsec` 표시가 없는 값 = 예전 평문 자료 → 읽고 다음 저장 때 암호화.
- 주요 레코드 키: 교육·훈련은 `"entries"`(기록 배열), 안전점검은 `"records"`, 화기작업은 `"entries"`.

## 4. 백업 파일 `.woomi`
- 바이트 구조: **1행 = 공개 JSON 헤더** `{"woomiBackup":1,"salt":b64,"iter":n,"iv":b64}` → `"\n"` → **그 뒤 = ciphertext 바이트**.
- 복호: 헤더의 salt·iter 로 비밀번호에서 키 유도 → AES-GCM 복호 → 평문 JSON.
- 평문 JSON: `{ app:"woomi", v:1, at, ls:{키:값...}, idb:{ DB이름:[[키,값],...] } }` (여기서 값은 복호화된 원본).
- ⚠️ 복원 시 `iter` 상·하한 검증이 없다 → **2단계에서 상·하한 검증 추가 예정**(호환성은 유지, 비정상 값만 거부).
- ⚠️ 백업에는 `site`·`manager` 프로필이 포함되지 않는다 → 새 PC 복원 시 별도 설정 필요(알려진 동작).

## 5. 범위 밖
- `exam/` 학습 앱은 별도 평문 저장소(`fire_elec_exam` 등)를 쓰며 본 계약과 무관하다. 재구성 시 별도 저장소/페이지로 분리 대상.

---

### 재구성 단계별 적용
- **1단계(패치 병합):** 저장 형식 변화 없음 — 계약 그대로.
- **2단계(보안):** `iter` 상·하한 검증만 추가(비정상 백업 거부). 기존 정상 백업·자료는 그대로 열림.
- **4단계(저장·암호화 재설계):** 기록 단위 암호화·AAD·키 래핑으로 바꾸는 단계. **여기서만** 위 포맷이 바뀌므로, "구 포맷 → 신 포맷" 마이그레이션 코드와 실데이터 모양 테스트를 통과해야 병합한다.
