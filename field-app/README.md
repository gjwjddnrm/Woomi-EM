# 현장점검 (안드로이드 앱)

상사와 현장을 돌며 대화를 계속 녹음하고, 지시가 나오면 사진을 찍어 두면
점검 후 **사진 + 그 시점 앞뒤 대화**가 시간순으로 묶인 타임라인과 보고서를 만들어 주는 앱입니다.
Expo(React Native, TypeScript) · 안드로이드 전용 · 데이터는 모두 폰 안(SQLite + 앱 저장소)에 저장됩니다.

## 기능

### 1단계 – 녹음·촬영·타임라인
- 현장명 입력 → **점검 시작** → 녹음이 바로 시작
- 녹음은 **Foreground Service**(상단 알림 "점검 녹음 중 · 현장명", 경과 시간 표시)에서 돌아갑니다.
  화면 꺼짐, 카메라, 다른 앱 전환, 최근 앱에서 밀어도 계속됩니다.
- **1분마다 새 파일**(AAC)로 저장. 앱이 강제 종료돼도 그 직전까지 남습니다.
- 통화가 오면 "통화 중"으로 표시하고, 끝나면 **자동으로 새 파일로 이어서 녹음**
- 녹음기 오류·멈춤을 2초마다 감시해 자동 재시작, 시스템이 서비스를 죽이면 다시 살아나 이어서 녹음
- 저장공간(300MB 미만)·배터리(15%, 5%) 부족 시 알림 경고, 시작 전에도 경고
- 촬영 화면: 카메라 + 큰 셔터 + **볼륨 버튼 셔터** + 진동, 빨간 점과 경과 시간 항상 표시
- 사진은 찍자마자 파일로 저장 → 뒤에서 1920px·JPEG 70%로 압축 (압축 중 꺼져도 원본 보존)
- 사진마다 점검 시작 기준 타임스탬프 + 한 줄 메모
- 앱을 다시 켜면 진행 중이던 점검을 찾아 **"이어서 녹음할까요?"**
- 타임라인: 사진별 **앞뒤 30초 녹음 재생**(±10초 이동), 녹음 파일 목록

### 2단계 – 정리
- 음성 → 텍스트: OpenAI Whisper (`whisper-1`, 한국어). 1분 조각씩 변환·저장, 끊겨도 이어서
- 사진별로 촬영 앞뒤 30초 대화를 자동 연결 (타임라인·PDF에 표시)
- Claude(`claude-opus-5-5`)로 **지적사항 / 조치 필요사항 / 담당·기한** 보고서 초안 (사진도 함께 보냄), 앱에서 바로 수정
- 사진이 들어간 A4 **PDF** 만들기 → 안드로이드 공유 창으로 카카오톡·메일 전송
- API 키는 설정 화면에서 입력, **SecureStore**(안드로이드 Keystore 암호화)에만 저장

## 폰에 설치하기 (APK)

### 1) APK 내려받기
이 저장소에서 `field-app/`이 바뀌어 푸시되면 GitHub Actions가 자동으로 APK를 만듭니다.

**방법 A – Releases (권장, 처음 한 번 설정 필요)**
- PC에서 저장소 **Settings → Actions → General → Workflow permissions → "Read and write permissions"** 선택 → Save.
  (이후 빌드부터 Releases에 APK가 올라갑니다. 이미 끝난 빌드는 Actions 화면에서 "Re-run all jobs".)
1. 폰 브라우저(크롬 또는 삼성 인터넷)로 `https://github.com/gjwjddnrm/Woomi-EM/releases` 를 엽니다.
2. 맨 위 **"현장점검 앱 v… (빌드 N)"** → Assets의 `field-inspection-v…-bN.apk`를 누릅니다.
3. "이 파일은 기기에 해를 끼칠 수 있습니다" 경고가 나오면 **"무시하고 다운로드"**.

**방법 B – Actions 결과물 (설정 없이, GitHub 로그인 필요)**
1. 폰 브라우저에서 GitHub에 로그인 → 저장소 **Actions** → **field-app APK** → 맨 위 초록색 ✓ 실행을 엽니다.
2. 아래쪽 **Artifacts**의 `field-inspection-v…-bN.apk`를 눌러 zip을 받습니다.
3. **내 파일 → 다운로드**에서 zip을 눌러 **압축 풀기** → 나온 `.apk`를 누릅니다.

### 2) 출처를 알 수 없는 앱 허용 (처음 한 번)
1. 다운로드 완료 알림(또는 내 파일 → 다운로드)에서 APK를 누릅니다.
2. "보안을 위해 이 출처의 알 수 없는 앱을 설치할 수 없습니다" → **설정** 을 누릅니다.
3. **"이 출처 허용"**(또는 "앱 설치 허용")을 켭니다.
   - 직접 찾아갈 때: 설정 → 애플리케이션 → (오른쪽 위 ⋮) **특별한 접근** → **알 수 없는 앱 설치** → 사용한 브라우저/내 파일 → **허용**
4. 뒤로 가서 **설치**.
5. "Play 프로텍트에서 앱을 스캔할까요?/차단했습니다"가 나오면 **"세부정보 더보기 → 그래도 설치"** (또는 "스캔 없이 설치").
6. 설치가 끝나면 보안을 위해 3번의 "이 출처 허용"을 다시 꺼도 됩니다.

### 3) 앱 첫 실행 – 녹음 안정성 설정 (꼭 하세요)
앱이 처음 열리면 안내 화면이 나옵니다.
1. **권한 허용**: 마이크·카메라·알림 → 모두 "허용" (마이크는 "앱 사용 중에만 허용")
2. **배터리 최적화 예외 요청** → 나오는 창에서 **허용**
3. **삼성 절전 예외 앱 등록**
   - 설정 → **배터리** → **백그라운드 사용 제한** → **절전 예외 앱** → ＋ → "현장점검" 추가
   - 같은 화면에서 "사용하지 않는 앱을 절전 상태로 전환" **끄기**
   - 설정 → 애플리케이션 → 현장점검 → **배터리** → **제한 없음**
   (앱의 "배터리 설정 열기", "앱 정보 열기" 버튼으로 바로 갈 수 있습니다.)

### 업데이트
새 APK를 같은 방법으로 설치하면 **데이터를 유지한 채** 업데이트됩니다(같은 서명).
앱을 지우면 폰 안의 점검 기록·녹음·사진도 함께 지워지니 주의하세요.

## 현장 테스트 체크리스트
기준: **30분 이상 연속 녹음 + 사진 20장 이상 + 중간에 화면 끄기와 다른 앱 전환**

| # | 할 일 | 확인할 것 |
|---|---|---|
| 1 | 점검 시작, 상단 알림 확인 | "점검 녹음 중 · 현장명"과 경과 시간이 보임 |
| 2 | 5분 녹음 중 사진 5장 (셔터 3장, 볼륨 버튼 2장) | 찍을 때마다 진동, "사진 N" 숫자 증가 |
| 3 | 전원 버튼으로 화면 끄고 5분 대기 | 다시 켜도 경과 시간이 이어지고 빨간 점이 깜박임 |
| 4 | 홈 버튼 → 카톡·지도 등 다른 앱 5분 사용 | 알림이 계속 떠 있음 |
| 5 | 다른 폰으로 전화 걸어 1분 통화 후 끊기 | 통화 중 "통화 중" 표시 → 끝나면 자동으로 "녹음 중" |
| 6 | 최근 앱 목록에서 앱을 밀어서 닫기 | 알림이 남아 있고 녹음 계속 |
| 7 | 총 30분 이상, 사진 20장 이상 채우고 **점검 종료** | 타임라인에 사진 20장, 녹음 30분 이상 (녹음 파일 목록 ≈ 30개+) |
| 8 | 사진 몇 장에서 "앞뒤 30초 듣기" | 그 시점 대화가 들림 (빨간 선 = 촬영 순간) |
| 9 | (선택) 점검 중 설정 → 애플리케이션 → 현장점검 → 강제 중지 후 앱 다시 열기 | "이어서 녹음할까요?" → 이어서 녹음, 직전 1분까지 녹음 남아 있음 |

문제가 생기면 **그 시각, 어떤 동작 중이었는지, 알림 문구**를 알려 주세요.

## 개발

```bash
cd field-app
npm ci
npx tsc --noEmit                              # 타입 검사
npx expo prebuild --platform android --clean  # android/ 생성 (커밋하지 않음)
cd android && ./gradlew assembleRelease       # APK: android/app/build/outputs/apk/release/
```

- 녹음 네이티브 모듈: `modules/field-recorder/` (Kotlin, Expo Modules API)
  - `RecorderService.kt` – Foreground Service, 1분 분할, 통화·멈춤 감시, 경고 알림
  - `AdtsUtil.kt` – AAC 조각 길이 계산, 구간 잘라 m4a 만들기(재생·Whisper용)
  - `VolumeKeyBridge.kt` + `plugins/withVolumeKeys.js` – 볼륨 버튼 셔터
- 데이터: `src/db.ts`(SQLite WAL), 점검별 폴더 `files/inspections/<id>/{audio,photos,exports}`

### 빌드 방법 두 가지
1. **GitHub Actions** (`.github/workflows/field-app-apk.yml`) – 계정 없이 자동. Expo 템플릿 서명키로 서명되어
   빌드끼리 서로 업데이트가 됩니다. 테스트용으로 씁니다.
2. **EAS Build** – Expo 계정이 필요합니다. PC에서:
   ```bash
   cd field-app
   npx eas-cli@latest login
   npx eas-cli@latest init          # 처음 한 번 (app.json에 projectId 추가 → 커밋)
   npx eas-cli@latest build -p android --profile preview
   ```
   끝나면 나오는 링크/QR을 폰으로 열어 APK를 받습니다. GitHub에 `EXPO_TOKEN` 비밀값을 넣으면
   Actions의 "Run workflow → EAS Build로도 빌드"로도 돌릴 수 있습니다.
   ⚠ EAS는 서명키가 달라서, Actions APK가 깔린 폰에 EAS APK를 덮어 설치할 수 없습니다(지우고 다시 설치 = 데이터 삭제).
   계속 쓸 정식판은 한 가지 방식으로 정해 주세요.

### 디자인 미리보기 (웹)
실제 폰 없이 화면 디자인을 확인할 때 씁니다. `*.web.ts(x)` 파일이 가짜 데이터·녹음 모듈·카메라를 대신합니다(앱에는 들어가지 않음).
```bash
npx expo export --platform web --output-dir /tmp/web && cp -r preview /tmp/web/
python3 -m http.server 8765 --directory /tmp/web   # http://localhost:8765/#home, #capture:demo-active, #timeline:demo1, #report:demo1
```
